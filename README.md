# MTProxy — набор скриптов для развёртывания на VPS

## 1. Назначение

Данный репозиторий содержит набор автономных shell-скриптов для
установки MTProxy (прокси-сервера протокола MTProto, используемого
мессенджером Telegram) на сервер под управлением Linux. Каждый скрипт
представляет собой готовое к использованию решение: он самостоятельно
устанавливает зависимости, разворачивает сервис, настраивает автозапуск
через systemd, открывает необходимый порт в файрволе и по завершении
выводит ссылку для подключения в формате `tg://proxy?...`.

Репозиторий рассчитан на сценарий частой смены серверов: вместо того
чтобы каждый раз настраивать прокси вручную, достаточно выполнить одну
команду на новом хосте.

## 2. Что такое MTProxy

MTProxy — прокси-сервер, реализующий протокол MTProto Proxy. Он
позволяет клиенту Telegram подключаться к серверам Telegram через
промежуточный узел, что используется для обхода блокировок на уровне
провайдера. В отличие от VPN, MTProxy проксирует только трафик
Telegram и не требует установки дополнительного клиентского
программного обеспечения — достаточно перейти по ссылке вида
`tg://proxy?server=...&port=...&secret=...`, и клиент Telegram
применит настройки автоматически.

Существует несколько независимых реализаций протокола. В этом
репозитории представлены четыре из них, различающиеся языком
реализации, требованиями к окружению и потреблением ресурсов.

## 4. Сравнение вариантов

| Критерий | mtg (бинарник) | mtg (Docker) | Официальный MTProxy | Python mtprotoproxy |
|---|---|---|---|---|
| Язык реализации | Go | Go (в контейнере) | C | Python 3 |
| Потребление RAM в простое | ~10–15 МБ | ~15–25 МБ + демон Docker | ~5–10 МБ | ~20–30 МБ |
| Требуемые пакеты | отсутствуют (статический бинарник) | Docker Engine | компилятор, `libssl-dev`, `zlib1g-dev` | `python3`, `pip3` |
| Время установки | секунды | 1–2 минуты (если Docker не установлен) | 1–3 минуты (компиляция) | ~1 минута |
| Маскировка трафика (fake-TLS) | да | да | нет (классический режим) | да |
| Обновление служебных файлов | не требуется | не требуется | требуется (см. п. 7.3) | не требуется |
| Рекомендуемое применение | сценарий по умолчанию | сервер уже использует Docker | минимальный footprint, официальная реализация | VPS без компилятора (OpenVZ, урезанные тарифы) |

**Рекомендация.** Если нет специфических требований — использовать
`install_mtproxy.sh` (`mtg`). Это современная реализация с поддержкой
маскировки трафика под TLS (fake-TLS), не требующая компиляции и
предоставляемая в виде единого статического бинарного файла.

## 5. Требования

- Сервер под управлением Linux с systemd (Ubuntu 20.04+, Debian 10+,
  CentOS 8+ и совместимые дистрибутивы).
- Доступ по SSH с правами `root` (либо `sudo`).
- Исходящий доступ в интернет (для загрузки бинарных файлов/пакетов и
  определения внешнего IP-адреса сервера).
- Свободный порт 443 (либо иной порт, задаваемый переменной
  окружения — см. п. 6).

## 6. Порядок установки

### 6.1. Публикация репозитория

Для запуска скриптов одной командой на произвольном сервере
репозиторий следует опубликовать в системе контроля версий (например,
GitHub). Поскольку сами скрипты не содержат конфиденциальных данных —
секрет генерируется непосредственно на целевом сервере в момент
установки, — репозиторий может быть публичным. Публичный репозиторий
не требует авторизации при загрузке файлов через `curl`.

```bash
git init
git add install_mtproxy.sh install_mtg_docker.sh install_official_mtproxy.sh install_python_mtprotoproxy.sh README.md
git commit -m "Add MTProxy installation scripts"
git branch -M main
git remote add origin https://github.com/<пользователь>/<репозиторий>.git
git push -u origin main
```

### 6.2. Запуск на сервере

Подключитесь к серверу по SSH и выполните одну из команд, в
зависимости от выбранного варианта. Команда должна выполняться с
правами `root`:

```bash
# mtg — вариант по умолчанию
bash <(curl -fsSL https://raw.githubusercontent.com/<пользователь>/<репозиторий>/main/install_mtproxy.sh)

# mtg в Docker-контейнере
bash <(curl -fsSL https://raw.githubusercontent.com/<пользователь>/<репозиторий>/main/install_mtg_docker.sh)

# Официальная реализация Telegram (C)
bash <(curl -fsSL https://raw.githubusercontent.com/<пользователь>/<репозиторий>/main/install_official_mtproxy.sh)

# Python-реализация без компиляции
bash <(curl -fsSL https://raw.githubusercontent.com/<пользователь>/<репозиторий>/main/install_python_mtprotoproxy.sh)
```

По завершении выполнения скрипт выводит в терминал:

- внешний IP-адрес сервера;
- используемый порт;
- секрет подключения;
- готовую ссылку вида `tg://proxy?server=...&port=...&secret=...`
  для передачи клиенту Telegram (открывается непосредственно на
  устройстве с установленным приложением Telegram);
- ссылку вида `https://t.me/proxy?...` для передачи через любой
  канал, не поддерживающий кастомные URL-схемы.

### 6.3. Параметры установки

Поведение каждого скрипта настраивается переменными окружения,
задаваемыми перед вызовом команды.

| Скрипт | Переменная | Значение по умолчанию | Назначение |
|---|---|---|---|
| `install_mtproxy.sh` | `MTG_PORT` | `443` | Порт прослушивания |
| | `MTG_DOMAIN` | `www.google.com` | Домен для маскировки трафика (fake-TLS) |
| `install_mtg_docker.sh` | `MTG_PORT` | `443` | Порт прослушивания |
| | `MTG_DOMAIN` | `www.google.com` | Домен для маскировки трафика (fake-TLS) |
| `install_official_mtproxy.sh` | `MTPROXY_PORT` | `443` | Порт прослушивания |
| `install_python_mtprotoproxy.sh` | `MTP_PORT` | `443` | Порт прослушивания |
| | `MTP_DOMAIN` | `www.google.com` | Домен для маскировки трафика (TLS-режим) |

Пример запуска с нестандартным портом и доменом маскировки:

```bash
MTG_PORT=8443 MTG_DOMAIN=www.microsoft.com bash <(curl -fsSL https://raw.githubusercontent.com/<пользователь>/<репозиторий>/main/install_mtproxy.sh)
```

**Рекомендация по выбору домена маскировки (`*_DOMAIN`).** Следует
указывать домен, реально доступный по HTTPS и не связанный с
Telegram — трафик клиентов, не прошедших проверку секрета, будет
прозрачно перенаправлен на этот домен, что затрудняет
идентификацию прокси при анализе трафика методом активного
зондирования.

## 7. Особенности отдельных вариантов

### 7.1. `install_mtproxy.sh` и `install_mtg_docker.sh` (mtg)

Используют официальные релизы проекта `mtg`, загружаемые с GitHub.
Секрет генерируется командой `mtg generate-secret`, что обеспечивает
поддержку режима fake-TLS «из коробки». Управление сервисом:

```bash
# бинарная установка
systemctl status mtg
journalctl -u mtg -f
systemctl restart mtg

# Docker-установка
docker logs -f mtg
docker restart mtg
```

### 7.2. `install_official_mtproxy.sh` (официальная реализация Telegram)

Скрипт клонирует исходный код из репозитория
`TelegramMessenger/MTProxy` и выполняет сборку командой `make`.
Официальная реализация не поддерживает маскировку под TLS —
используется секрет в открытом виде.

Особенность данной реализации заключается в том, что сервер
использует конфигурационные файлы `proxy-secret` и
`proxy-multi.conf`, периодически изменяемые Telegram на стороне их
инфраструктуры. Скрипт настраивает systemd-таймер
(`mtproxy-update.timer`), выполняющий ежесуточное обновление этих
файлов с последующим перезапуском сервиса. Отключение автообновления
не рекомендуется, так как устаревшие файлы конфигурации могут
привести к неработоспособности прокси.

Управление сервисом:

```bash
systemctl status mtproxy
journalctl -u mtproxy -f
systemctl restart mtproxy

# проверка таймера автообновления конфигурации
systemctl list-timers mtproxy-update.timer
```

### 7.3. `install_python_mtprotoproxy.sh` (Python-реализация)

Не требует наличия компилятора — единственная зависимость,
устанавливаемая скриптом, это интерпретатор Python 3 и, по
возможности, библиотека `uvloop`, повышающая производительность
обработки сетевых событий (при недоступности пропускается без
прерывания установки).

В режиме fake-TLS секрет подключения формируется программой
`mtprotoproxy.py` в формате `ee<hex-секрет><hex-домен>` — данный
формат не воспроизводится в самом скрипте во избежание ошибок
формирования строки; вместо этого готовая ссылка считывается
непосредственно из журнала systemd после запуска сервиса:

```bash
journalctl -u mtprotoproxy --no-pager | grep 'tg://proxy'
```

Управление сервисом:

```bash
systemctl status mtprotoproxy
journalctl -u mtprotoproxy -f
systemctl restart mtprotoproxy
```

## 8. Повторный запуск и обновление

Все скрипты спроектированы как идемпотентные: повторное выполнение на
том же сервере обновит бинарный файл (либо исходный код — для
официальной реализации), сгенерирует новый секрет и перезапустит
сервис с новой конфигурацией. Это также является рекомендуемым
способом ротации секрета подключения без необходимости переустановки
операционной системы.

## 9. Диагностика неисправностей

| Симптом | Возможная причина | Действие |
|---|---|---|
| Скрипт завершается с ошибкой `Run this script as root` | Команда выполнена без прав администратора | Повторить запуск через `sudo` либо под пользователем `root` |
| Сервис не запускается | Порт уже занят другим процессом | Проверить `ss -tlnp \| grep <порт>`, выбрать другой порт через `*_PORT` |
| Клиент Telegram не подключается | Порт закрыт на уровне облачного провайдера (Security Group / Cloud Firewall) | Открыть порт в панели управления облачного провайдера — локальный файрвол сервера скрипт настраивает автоматически, внешний — нет |
| Не удаётся определить внешний IP-адрес | Отсутствует исходящий доступ к `api.ipify.org` / `ifconfig.me` | Указать IP-адрес сервера вручную при формировании ссылки подключения |
| Официальный MTProxy перестал работать спустя некоторое время | Не выполняется обновление `proxy-secret` / `proxy-multi.conf` | Проверить статус `mtproxy-update.timer`, при необходимости выполнить `systemctl start mtproxy-update.service` вручную |

## 10. Замечания по безопасности

- Секрет подключения предоставляет полный доступ к использованию
  прокси-сервера от имени владельца сервера. Ссылку следует
  передавать только доверенным получателям.
- Для затруднения обнаружения прокси методом активного зондирования
  рекомендуется использовать реализации с поддержкой fake-TLS
  (`mtg`, `mtprotoproxy` в TLS-режиме) и указывать в качестве домена
  маскировки (`*_DOMAIN`) реально существующий и не связанный с
  Telegram ресурс.
- Все сервисы запускаются от имени непривилегированного пользователя
  (`nobody`) с ограниченными правами — привязка к порту ниже 1024
  обеспечивается через `AmbientCapabilities=CAP_NET_BIND_SERVICE`
  (mtg) без предоставления полных прав `root` рабочему процессу.
